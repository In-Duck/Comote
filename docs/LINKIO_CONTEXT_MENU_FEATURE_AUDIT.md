# LinkIO 컴퓨터 우클릭 메뉴 기능 분석

작성일: 2026-07-17  
분석 대상: LinkIO v2.7.10 화면, 설치 폴더, 내장 패치노트, 현재 Comote 소스

## 1. 결론

사진 속 우클릭 메뉴는 다음 세 범주다.

1. **목록/그룹 데이터 관리**
   - 전체 선택
   - 새 그룹으로
   - 기존 그룹으로 이동
   - 이름/메모 변경
   - 순서 변경
   - 삭제
2. **원격 연결/세션 제어**
   - 컨트롤 창 열기
   - 로그아웃
   - 입력제어 전환
   - 외부원격 실행
3. **원격 시스템 관리**
   - 드라이버 설치/삭제
   - 원격 프로그램 재실행
   - Windows 재부팅
   - Windows 시스템 종료

현재 Comote는 원격 화면 연결, 입력, 단순 순서 변경, 삭제, 파일 전송, Wake-on-LAN은 구현되어 있다. 그러나 사진 속 메뉴 기준으로는 **컨트롤 창 열기만 부분 구현**, **앞/뒤 순서 변경과 삭제만 구현**, 나머지 대부분은 UI와 Host 명령 처리 모두 미구현이다.

Supabase 초기 마이그레이션에는 그룹 테이블과 원격 작업 테이블이 준비되어 있지만 Viewer/Host가 아직 이를 사용하지 않는다.

---

## 2. LinkIO에서 확인된 근거

설치 폴더의 `LinkIO_v2.exe` 내장 패치노트에서 다음 기능을 확인했다.

- v2.7.10: 다중 제어창에서 여러 제어창을 한 번에 열도록 수정
- v2.7.2: 우클릭 메뉴에 드라이버 설치/삭제 추가
- v2.7.1: 우클릭 메뉴에 입력 모드 전환 추가
- v2.7.0: 연결된 클라이언트 로그아웃 및 멀티 모니터 지원
- 연결되지 않은 클라이언트도 재실행할 수 있도록 개선한 기록
- 원격 컴퓨터 재부팅 및 시스템 종료 안정화 기록
- 리스트/그룹의 이름과 메모 동기화 기록
- 빈 그룹 생성, 그룹 이동, 그룹 순서 저장 기록
- 그룹에서도 외부원격을 실행하도록 추가한 기록

`list.json` 구조에서는 다음 필드를 확인했다.

- 외부 IP
- 내부 IP
- 세션 ID
- 외부원격 ID
- 이름
- 메모

따라서 `외부원격 실행`은 LinkIO 화면 스트리밍 자체가 아니라, 컴퓨터별로 저장된 외부 원격 프로그램 ID를 이용해 별도 원격 프로그램을 여는 기능으로 판단된다. 정확히 어떤 외부 원격 제품을 실행하는지는 현재 자료만으로 확정할 수 없다.

## 3. 항목별 분석

### 3.1 `임대17 - 컨트롤 창 열기`

**LinkIO 동작**

- 선택한 컴퓨터의 독립 원격 제어창을 연다.
- 이름이 메뉴 제목에 포함된다.
- 패치노트상 여러 컴퓨터의 제어창을 한 번에 여는 다중 제어창 모드도 존재한다.
- 창 위치, 최대화 상태, 이전/다음 컴퓨터 전환 상태를 기억하는 기능이 있다.

**현재 Comote**

- 목록 더블클릭 또는 카드의 `Connect` 버튼으로 원격 화면을 연다.
- 별도 창이 아니라 Viewer 메인 창 내부가 원격 화면으로 전환된다.
- 한 번에 한 Host만 연결한다.

**판정: 부분 구현**

**필요 작업**

- `RemoteControlWindow`를 별도 WPF 창으로 분리
- 컴퓨터별 독립 `VideoReceiver` 수명 관리
- 동시에 여러 제어창을 열 수 있는 세션 관리자
- 창 위치/크기/최대화 상태 저장
- 이미 열린 컴퓨터를 다시 열 때 기존 창 활성화
- 온라인 상태와 권한 확인

---

### 3.2 `전체 선택 (Ctrl+A)`

**LinkIO 동작**

- 현재 리스트 또는 현재 그룹의 모든 컴퓨터를 선택한다.
- 이후 그룹 이동, 재실행, 재부팅 같은 일괄 작업의 대상이 된다.

**현재 Comote**

- DataGrid가 `SelectionMode.Single`이라 한 대만 선택할 수 있다.
- 파일 전송 코드는 `SelectedItems`를 순회하지만 UI가 단일 선택이라 실제 다중 선택과 맞지 않는다.

**판정: 미구현**

**필요 작업**

- `SelectionMode.Extended`로 변경
- Ctrl/Shift 선택과 Ctrl+A 지원
- 카드 보기에도 선택 상태와 체크 UI 제공
- 메뉴에 `(N개)` 선택 수를 실시간 표시
- 일괄 작업 전 대상 목록을 고정해 선택 변경과 작업 대상이 섞이지 않도록 처리

---

### 3.3 `(1개) 새 그룹으로`

**LinkIO 동작**

- 선택한 컴퓨터들로 새 그룹을 만든다.
- 그룹 이름 입력 후 선택 항목을 새 그룹에 넣는다.
- 그룹별 화면 열 수, 비율, 프레임, 품질 같은 설정을 따로 저장한다.

**현재 Comote**

- DB 마이그레이션에 `device_groups`, `device_group_members`가 준비되어 있다.
- Viewer에는 그룹 생성 UI와 Repository가 없다.

**판정: 기반만 준비됨**

**필요 작업**

- 그룹 생성 대화상자
- 그룹 Repository/API
- 그룹 탭과 빈 그룹 처리
- 중복 그룹명 검증
- 생성과 멤버 추가를 하나의 서버 트랜잭션으로 처리
- 그룹별 레이아웃/모니터링 설정 저장

---

### 3.4 `(1개) 기존 그룹으로 이동`

**LinkIO 동작**

- 하위 메뉴에 기존 그룹 목록을 표시한다.
- 선택한 컴퓨터를 목표 그룹으로 이동한다.
- LinkIO 패치노트상 그룹 추가 후 저장되지 않던 문제와 삭제된 컴퓨터가 그룹에 남던 문제가 수정된 이력이 있다.

**현재 Comote**

- DB 관계와 Host 삭제 시 그룹 멤버가 같이 삭제되는 외래키는 준비되어 있다.
- Viewer 동작은 없다.

**판정: 기반만 준비됨**

**필요 작업**

- 메뉴를 열 때 최신 그룹 목록 로드
- 이동과 복사 정책 결정
  - 사진의 문구는 `이동`이므로 기존 그룹에서는 제거하는 것이 기본
  - 여러 그룹 동시 소속을 허용할지 제품 정책 확정 필요
- 다중 선택 일괄 이동
- 현재 그룹과 같은 그룹은 비활성화

---

### 3.5 `이름/메모 변경 (F2)`

**LinkIO 동작**

- 선택한 컴퓨터의 사용자 지정 이름과 메모를 편집한다.
- 변경값이 리스트와 그룹, 다른 Viewer 접속에도 동기화된다.

**현재 Comote**

- `host_name`은 Host가 heartbeat로 보고한다.
- 별도 사용자 지정 이름과 메모 필드가 없다.
- Viewer 편집 UI가 없다.

**판정: 미구현**

**필요 작업**

- `display_name`, `memo` 필드 추가
- Host가 보고하는 실제 컴퓨터 이름과 사용자가 정한 표시 이름 분리
- F2 편집 창
- 낙관적 UI 갱신 후 서버 실패 시 롤백
- 여러 Viewer에서 변경될 때 실시간 또는 주기 동기화

---

### 3.6 `순서 변경: 앞으로`

**LinkIO 동작**

- 선택 항목을 한 칸 앞으로 이동한다.

**현재 Comote**

- `MoveHost(-1)`로 구현되어 있다.
- 로컬 Viewer 설정의 `HostOrder`에만 저장된다.

**판정: 로컬 한정 구현**

**필요 작업**

- 그룹별 `sort_order`를 서버에 저장
- 다른 Viewer에서도 같은 순서 동기화
- 다중 선택 시 상대 순서를 유지하며 이동

---

### 3.7 `순서 변경: 뒤로`

**LinkIO 동작**

- 선택 항목을 한 칸 뒤로 이동한다.

**현재 Comote**

- `MoveHost(1)`로 구현되어 있다.
- 로컬 Viewer에만 저장된다.

**판정: 로컬 한정 구현**

**필요 작업**

- 3.6과 동일

---

### 3.8 `순서 변경: 원하는 위치로...`

**LinkIO 동작**

- 숫자 또는 대상 위치를 입력하여 선택 항목을 해당 위치로 이동한다.

**현재 Comote**

- 앞/뒤 한 칸 이동만 있다.

**판정: 미구현**

**필요 작업**

- 위치 입력 대화상자
- 범위 검증
- 다중 선택 블록 이동
- 전체 순서의 충돌 없는 재번호 부여

---

### 3.9 `(1개) 삭제`

**LinkIO 동작**

- 관리 목록에서 컴퓨터를 삭제한다.
- 패치노트상 삭제 시 그룹에서도 함께 제거한다.
- 실행 중인 원격 Host 프로그램을 제거하는 기능과는 별개다.

**현재 Comote**

- 확인창 후 Supabase `hosts` 행을 삭제한다.
- 로컬 순서에서도 제거한다.
- DB 외래키에 의해 그룹 멤버도 함께 삭제된다.

**판정: 구현됨**

**보완 필요**

- Host가 계속 실행 중이면 다음 heartbeat에서 다시 등록될 수 있다.
- `삭제`와 `등록 해제/차단`을 분리해야 한다.
- 재등록 방지를 위한 `revoked_devices` 또는 등록 승인 상태가 필요하다.
- 썸네일 파일과 관련 작업 기록 정리 정책 필요

---

### 3.10 `(1개) 로그아웃`

**LinkIO 동작**

- 선택한 원격 LinkIO 클라이언트를 현재 LinkIO 계정에서 로그아웃시키는 기능으로 판단된다.
- Windows 사용자 세션 로그오프와는 다른 기능일 가능성이 높다.
- 근거는 패치노트의 “연결된 클라이언트 로그아웃” 표현과, 같은 시기의 “이전 아이디로 연결됐던 클라이언트” 처리 기록이다.
- 정확한 확인을 위해 실행 전 확인창 또는 실행 직후 클라이언트 화면 자료가 있으면 좋다.

**현재 Comote**

- 원격 장치의 계정 연결 해제/등록 해제 명령이 없다.
- DB 작업 enum의 `logoff`는 Windows 세션 로그오프를 뜻하도록 설계되어 있어 이 메뉴와 직접 대응하지 않는다.

**판정: 미구현**

**필요 작업**

- `unlink_device` 또는 `sign_out_agent` 작업 타입 추가
- Host의 refresh token과 서비스 자격 증명 삭제
- 현재 소유자의 Host 목록에서 등록 해제
- 실행 즉시 원격 연결 종료
- 다시 연결하려면 Host에서 사용자 로그인이 필요하도록 처리
- 단순 목록 삭제와 원격 클라이언트 로그아웃을 명확히 분리

---

### 3.11 `(1개) 입력제어 전환`

**LinkIO 동작**

- 하위 메뉴는 `모드1`, `모드2`, `모드3` 세 가지다.
- 모드1은 설치 메뉴에 없으므로 별도 드라이버가 필요 없는 기본 입력 방식으로 판단된다.
- 모드2와 모드3은 각각 대응하는 드라이버 설치 후 사용할 수 있는 입력 방식으로 판단된다.
- 설치 메뉴에는 모드2와 모드3만 있다.
- 삭제 메뉴에는 구버전, 모드2, 모드3이 있다.
- `구버전`은 과거 클라이언트가 설치했던 이전 드라이버를 정리하기 위한 호환성 항목으로 보인다.
- 모드2와 모드3의 정확한 주입 기술 차이는 화면과 컨트롤러 실행 파일만으로는 확정할 수 없다.

**현재 Comote**

- Host의 `InputSimulator`가 Windows `SendInput`을 사용한다.
- 현재 Comote에는 모드 전환 UI나 드라이버 입력 경로가 없다.

**판정: 단일 모드만 구현**

**필요 작업**

- `IInputBackend` 인터페이스로 입력 구현 분리
- `표준 모드`: 현재 `SendInput` 구현
- `드라이버 모드2`: 패키지와 기술을 확정한 뒤 Adapter 추가
- `드라이버 모드3`: 패키지와 기술을 확정한 뒤 별도 Adapter 추가
- Host 상태에 설치된 드라이버와 현재 입력 모드 보고
- 전환 전에 해당 드라이버의 설치/실행 상태 확인
- 드라이버 오류 시 표준 모드로 안전하게 복귀
- UAC/보안 데스크톱에서는 일반 사용자 프로세스 입력이 제한됨을 UI에 표시
- Host 서비스와 사용자 세션 Helper 프로세스 사이 IPC 설계

---

### 3.12 `(1개) 드라이버 삭제`

**LinkIO 동작**

- 하위 메뉴는 `구버전`, `모드2`, `모드3`이다.
- 구버전은 과거 버전의 입력 드라이버 제거용으로 판단된다.
- 모드2는 모드2용 현재 드라이버만 제거한다.
- 모드3은 모드3용 현재 드라이버만 제거한다.
- 세 항목이 분리된 점으로 보아 서로 다른 Driver/Service/Device ID를 사용한다.
- 정확한 드라이버 제품명과 Hardware ID는 원격 클라이언트 설치 파일 또는 설치 전후 장치 관리자 비교가 있어야 확정할 수 있다.

**현재 Comote**

- 원격 드라이버 관리 기능과 드라이버 패키지가 없다.

**판정: 미구현**

**필요 작업**

- Host가 설치된 입력 드라이버 목록과 버전을 보고
- 구버전 정리 작업을 현재 드라이버 제거와 분리
- 정확한 Hardware ID와 패키지 ID를 허용 목록으로 관리
- 관리자 권한 Host 서비스에서만 실행
- 제거 후 실제 장치/서비스 소멸 여부 확인
- 재부팅 필요 상태 보고
- 임의 INF 경로나 명령을 Viewer가 보내지 못하도록 허용 목록 사용

---

### 3.13 `(1개) 드라이버 설치`

**LinkIO 동작**

- 선택한 컴퓨터에 지정 드라이버를 원격 설치한다.
- 하위 메뉴는 `모드2`, `모드3`만 제공한다.
- 모드1은 설치 대상이 아니므로 Windows 기본 입력 API를 사용하는 호환 모드로 보는 것이 타당하다.
- 사용자는 원격 PC 환경에 따라 모드2 또는 모드3 드라이버를 골라 설치할 수 있다.
- 서로 다른 두 드라이버를 동시에 설치할 수 있는지는 현재 화면만으로 확정되지 않는다.

**현재 Comote**

- 미구현

**판정: 미구현**

**필요 작업**

- 모드2와 모드3 패키지 및 설치 작업을 완전히 분리
- 패키지 해시와 전자서명 검증
- OS 버전/아키텍처 호환성 검사
- 관리자 권한 Host 서비스에서만 설치
- 설치 진행률과 결과 코드
- 설치 성공과 장치 활성화를 확인한 뒤에만 해당 모드로 전환
- 실패하면 표준 모드로 유지
- 재부팅 필요 여부
- 실패 시 복구/롤백

---

### 3.14 `(1개) 원격 프로그램 재실행 (업데이트)`

**LinkIO 동작**

- 원격 PC의 LinkIO 클라이언트/Host 프로그램을 재시작한다.
- 괄호의 `업데이트`는 업데이트 파일 적용 후 재실행하는 용도까지 포함하는 것으로 보인다.
- 패치노트상 연결되지 않은 상태에서도 재실행이 가능하도록 개선된 기록이 있다.

**현재 Comote**

- Host 시작 시 AutoUpdater 기능은 있다.
- Viewer에서 Host 재시작 작업을 내리는 기능은 없다.
- Host 서비스가 종료/재시작을 관리하는 Supervisor 구조도 불완전하다.

**판정: 자동 업데이트만 부분 구현**

**필요 작업**

- `restart_agent` 작업 타입 추가
- 서비스 자체가 아닌 사용자 세션 Host 프로세스를 안전하게 재시작
- 업데이트 다운로드, 해시/서명 검증, 설치, 재접속까지 상태 추적
- 실행 파일이 죽어도 서비스를 통해 복구
- 명령 전송 채널과 업데이트 다운로드 채널 분리

---

### 3.15 `(1개) 원격 윈도우 재부팅`

**LinkIO 동작**

- 선택한 Windows PC를 재부팅한다.
- 다중 선택 일괄 실행이 가능하다.

**현재 Comote**

- DB enum에 `restart`가 있지만 생성/수신/실행 흐름은 없다.

**판정: 서버 스키마만 준비됨**

**필요 작업**

- 위험 작업 확인창
- 온라인 Host에는 즉시 명령, 오프라인 Host에는 만료 시간이 짧은 예약 작업
- Host 서비스의 관리자 권한 실행
- 접수/실행 시작/종료 예정/재접속 결과 상태
- 중복 실행 방지용 idempotency key

---

### 3.16 `(1개) 원격 윈도우 시스템종료`

**LinkIO 동작**

- 선택한 Windows PC를 종료한다.
- 종료 후에는 WoL이 설정된 장치만 원격으로 다시 켤 수 있다.

**현재 Comote**

- DB enum에 `shutdown`이 있지만 실행 흐름은 없다.
- Wake-on-LAN 전송은 부분 구현되어 있다.

**판정: WoL만 부분 구현**

**필요 작업**

- 재부팅보다 강한 2차 확인
- 원격 작업 상태는 종료 직전까지만 보고 가능하므로 `shutdown_accepted` 상태 정의
- AC 전원, WoL 지원 여부 표시
- 오프라인 예약 종료는 기본 금지 또는 매우 짧은 만료 시간 적용

---

### 3.17 `(1개) 외부원격 실행`

**LinkIO 동작**

- 컴퓨터별 `외부원격번호`/`remoteId`를 사용하여 외부 원격 프로그램을 연다.
- LinkIO 내장 화면 제어가 실패할 때 보조 접속 수단으로 보인다.

**현재 Comote**

- 외부 원격 ID 필드와 실행 기능이 없다.

**판정: 미구현**

**필요 작업**

- 지원 제품을 명시적으로 정해야 한다.
- 권장 1차 지원: Windows RDP 또는 사용자가 지정한 허용된 URI 템플릿
- 프로그램 경로와 인자를 자유 문자열로 저장하지 말고 제품별 Adapter 사용
- 외부 원격 ID는 암호가 아니지만 사용자 소유 데이터로 보호
- 설치 여부 확인 후 실행

## 5. 권장 구현 순서

### 1단계: 목록 기능

1. 다중 선택 및 Ctrl+A
2. 표시 이름/메모
3. 서버 동기화 순서
4. 새 그룹/기존 그룹 이동
5. 원하는 위치 이동

### 2단계: 원격 작업 기반

1. Viewer 작업 생성 API
2. Host 작업 수신/폴링
3. 작업 소유권, 서명, 만료 시간 검증
4. 상태/오류/감사 로그
5. 중복 실행 방지

### 3단계: 안전한 시스템 명령

1. Host 프로그램 재실행
2. Windows 로그아웃
3. Windows 재부팅
4. Windows 종료

### 4단계: 컨트롤 UX

1. 별도 컨트롤 창
2. 다중 컨트롤 창
3. 창 위치와 상태 기억
4. 이전/다음 컴퓨터 전환

### 5단계: 선택 기능

1. 외부원격 Adapter
2. 입력 방식 전환
3. 서명된 드라이버 설치/삭제

드라이버 기능은 종류와 필요성이 확정되기 전에는 구현하지 않는 것이 안전하다. 현재 목표인 일반 다중 컴퓨터 원격 제어는 표준 `SendInput`과 Host 서비스/사용자 세션 Helper 구조로 먼저 완성할 수 있다.
