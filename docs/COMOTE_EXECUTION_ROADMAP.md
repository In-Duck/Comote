# Comote 다중 컴퓨터 원격 제어 개발 로드맵

작성일: 2026-07-17  
개발 방향: **SendInput 기반 제품 완성 후 Comote 자체 Virtual HID 드라이버 추가**

## 1. 제품 목표

Comote는 휴대폰 미러링을 제외하고 다음에 집중한다.

- 여러 Windows 컴퓨터 등록 및 상태 모니터링
- 한 대 또는 여러 대의 원격 화면 열기
- 키보드·마우스 원격 제어
- 그룹 및 순서 관리
- 여러 컴퓨터 대상 일괄 작업
- 파일 전송, 프로그램 실행·종료
- Host 재실행, 등록 해제, Windows 재부팅·종료
- 향후 자체 Virtual HID를 이용한 고급 입력

LinkIO의 프로그램, DLL, 드라이버는 복사하거나 재배포하지 않는다. 확인한 기능과 사용자 경험만 참고해 Comote 코드와 프로토콜을 독립적으로 구현한다.

## 3. 확정된 개발 원칙

1. 첫 제품은 `SendInput`으로 완성한다.
2. 입력 구현은 `IInputBackend` 뒤로 분리해 나중에 드라이버를 교체할 수 있게 한다.
3. 시스템 명령은 WebRTC 입력 메시지로 직접 실행하지 않는다.
4. 재부팅·종료·설치 같은 명령은 인증된 원격 작업 시스템을 사용한다.
5. 관리자 권한 서비스와 사용자 세션 Helper를 분리한다.
6. 위험 작업은 허용 목록, 만료 시간, 중복 방지 키, 감사 로그를 사용한다.
7. LinkIO 전용 드라이버와 DLL은 사용하지 않는다.
8. 자체 드라이버는 기본 제품이 안정화된 후 별도 단계로 개발한다.

## 단계 3. Host 서비스와 사용자 세션 Helper 분리

`SendInput`은 실제 로그인된 Windows 사용자 세션 안에서 실행되어야 한다.

### 구성

```text
ComoteHostService (LocalSystem)
    ├─ 로그인/작업/업데이트 관리
    ├─ 사용자 세션 감지
    └─ 제한된 Named Pipe IPC
             ↓
ComoteHostAgent (로그인 사용자 세션)
    ├─ 화면 캡처
    ├─ WebRTC
    ├─ SendInput
    ├─ 클립보드
    └─ 사용자 화면 UI
```

### 작업

- 기존 Host 실행 파일의 서비스 역할과 Agent 역할 분리
- 활성 사용자 세션에서 Agent 실행
- 세션 전환, 로그오프, 재로그인 처리
- Named Pipe ACL과 메시지 허용 목록
- Agent 비정상 종료 시 서비스가 재시작
- 서비스는 임의 명령이나 임의 실행 파일 경로를 받지 않도록 제한

### 완료 기준

- Windows 재부팅 후 서비스 자동 시작
- 사용자가 로그인하면 Agent 자동 실행
- 일반 바탕화면에서 SendInput 정상 동작
- Agent 강제 종료 후 자동 복구
- 세션 0에서 입력을 시도하지 않음

## 단계 4. SendInput 입력 계층 완성

### 코드 구조

```text
IInputBackend
    └─ SendInputBackend
```

향후 다음 구현을 추가한다.

```text
IInputBackend
    ├─ SendInputBackend
    ├─ ComoteVirtualHidMode2Backend
    └─ ComoteVirtualHidMode3Backend
```

### 작업

- 기존 `InputSimulator`를 `SendInputBackend`로 분리
- 입력 모드 enum과 현재 모드 상태 보고
- 키 Down/Up 상태 추적
- 연결 종료 시 눌린 키와 버튼 모두 해제
- 스캔코드, 확장키, 좌우 Ctrl/Alt/Shift 처리
- 숫자패드, 기능키, Windows 키 처리
- 한글/IME 입력 정책
- 절대/상대 마우스 이동
- 다중 모니터 좌표 변환
- 화면 배율 100% 이상 좌표 검증
- 드래그, 휠, X1/X2 버튼
- 입력 큐 크기 제한과 오래된 MouseMove 병합
- 비밀번호/UAC/보안 데스크톱 제한 안내

### 완료 기준

- 일반 Windows 앱에서 키보드·마우스 정상 동작
- Ctrl+Alt 조합, 방향키, 숫자패드 정상 동작
- 연결이 끊겨도 키가 눌린 상태로 남지 않음
- 다중 모니터와 DPI 배율에서 좌표 오차 없음
- 빠른 마우스 이동 중 입력 큐가 무한 증가하지 않음

## 단계 5. 원격 세션 보안과 제어권

### 작업

- WebRTC 연결마다 짧은 수명의 세션 nonce 발급
- DataChannel 첫 메시지에서 세션 인증
- 인증 전 입력과 파일 메시지 거부
- 한 Host를 여러 Viewer가 볼 수 있는지 정책 설정
- 제어권 소유자 한 명 또는 명시적 공유 모드
- `보기 전용`, `입력 가능`, `관리자 작업 가능` 권한 분리
- 입력 시작/종료 감사 로그
- rate limit과 메시지 크기 제한

### 완료 기준

- 소유권 없는 Viewer가 signaling 또는 입력 채널 사용 불가
- 인증되지 않은 DataChannel 메시지 무시
- 동시에 두 Viewer가 입력을 섞지 않음
- 제어 중인 Viewer와 보기 전용 Viewer가 UI에 표시

## 단계 6. 목록 UX와 우클릭 메뉴 1차

### 구현 순서

1. 다중 선택
2. Ctrl+A 전체 선택
3. 선택 수 `(N개)` 표시
4. 이름/메모 변경
5. 순서 변경: 앞으로
6. 순서 변경: 뒤로
7. 순서 변경: 원하는 위치로
8. 삭제와 등록 해제의 구분

### 데이터 변경

- `computer_name`: Host가 보고한 실제 이름
- `display_name`: 사용자가 지정한 표시 이름
- `memo`: 사용자 메모
- `sort_order`: 서버 동기화 순서
- `enrollment_status`: 승인/차단/등록 해제 상태

### 완료 기준

- 리스트와 카드 보기에서 같은 선택 상태 유지
- 여러 컴퓨터를 선택해 일괄 메뉴 실행 가능
- 이름/메모/순서가 다른 Viewer에도 동기화
- 삭제한 Host가 자동으로 재등록되지 않음

## 단계 9. 다중 제어창과 멀티컨트롤

### 작업

- 선택한 여러 컴퓨터의 제어창 일괄 열기

- 긴급 중지로 모든 멀티 입력 즉시 해제
- Host별 지연과 실패 상태 표시

## 단계 10. 원격 작업 시스템

### 작업 구조

```text
Viewer
  ↓ 작업 생성 API
remote_jobs / remote_job_targets
  ↓ Host 폴링 또는 인증된 push 알림
ComoteHostService
  ↓ 허용 작업 실행
결과/오류/감사 로그
```

### 공통 필드

- 작업 ID
- 생성 사용자
- 대상 Host
- 작업 종류
- 허용된 payload
- 생성 시각
- 만료 시각
- idempotency key
- queued/running/succeeded/failed/cancelled/expired 상태
- 결과 코드와 사용자용 메시지

### 완료 기준

- 오프라인 Host의 작업 만료 처리
- 같은 작업이 중복 실행되지 않음
- 사용자가 자기 Host에만 작업 생성
- Viewer에서 Host별 결과 확인

## 단계 11. 원격 시스템 명령

위험도가 낮은 순서로 추가한다.

1. Host Agent 재실행
2. Host 업데이트 적용
3. Host 계정 등록 해제
4. Windows 사용자 세션 잠금
5. Windows 사용자 세션 로그오프
6. Windows 재부팅
7. Windows 종료

### 안전 조건

- 재부팅과 종료는 2차 확인
- 일괄 명령은 대상 수와 이름 표시
- 오프라인 예약 작업은 짧은 만료 시간
- 재부팅 후 Host 재접속까지 추적
- 종료 후 WoL 가능 여부 표시

### 완료 기준

- 각 명령의 접수, 실행, 결과 상태 표시
- 권한 부족과 Windows 오류 코드 표시
- 감사 로그 기록

## 단계 13. 외부 원격 Adapter

### 작업

- 지원 제품을 명시적으로 선택
- 제품별 ID 필드 분리
- 설치 여부 확인
- 제품별 안전한 URI/프로세스 Adapter
- 임의 실행 파일 경로나 인자를 데이터베이스에서 직접 실행하지 않음

### 완료 기준

- 등록된 외부 원격 제품만 실행
- 잘못된 ID와 미설치 상태를 사용자에게 표시

---

## 단계 14. 배포와 운영 안정화

### 작업

- Host/Viewer 설치 프로그램 통합 검증
- 서비스 설치/업데이트/제거
- 자동 업데이트 서명 및 SHA-256 검증
- 이전 버전 롤백
- crash dump와 구조화 로그
- CPU/RAM/GPU/네트워크 부하 측정
- 10대, 50대, 100대 단계별 부하 시험
- 운영 백업과 장애 복구 문서

### 완료 기준

- 설치, 업데이트, 제거 후 잔여 서비스 없음
- 업데이트 실패 시 이전 버전 복구
- 장시간 모니터링에서 메모리 지속 증가 없음
- 서버 장애 후 자동 복구

---

## 단계 15. Comote 자체 Virtual HID

기본 제품이 안정화된 뒤 별도 프로젝트로 진행한다.

### 작업

- 요구사항 정의
  - 일반 앱 입력만 필요한지
  - UAC/로그인 화면까지 필요한지
  - 게임 및 Raw Input 호환이 필요한지
- WDK/KMDF Virtual HID Framework 기반 자체 드라이버
- 키보드, 상대 마우스, 절대 마우스 HID report descriptor
- Host 서비스와 드라이버 IOCTL 프로토콜
- 요청 크기, 호출자, 세션 검증
- 드라이버 패키지 버전 관리
- Microsoft 드라이버 서명 절차
- 설치, 제거, 업데이트, 롤백
- `ComoteVirtualHidBackend` 구현

### 금지 사항

- LinkIO SYS/DLL/INF 복사
- LinkIO 인증 방식 재사용 또는 우회
- LinkIO 장치 ID와 서비스명 재사용
- 서명된 INF/CAT 수정

### 완료 기준

- 자체 장치 ID, 자체 서비스명, 자체 코드
- 서명된 드라이버 설치 성공
- `SendInput`과 Virtual HID 모드 전환
- 드라이버 장애 시 `SendInput` fallback
- 제거 후 시스템에 장치와 서비스 잔여물 없음

## 6. 다음 즉시 작업

코드 작업의 첫 순서는 다음과 같다.

1. 새 Supabase가 준비되기 전에도 가능한 `IInputBackend` 분리
2. 기존 `InputSimulator`를 `SendInputBackend`로 이동
3. 연결 종료 시 모든 키와 마우스 버튼을 해제하는 안전장치
4. 입력 모드 상태 모델 추가
5. Host/Viewer 빌드 및 기존 원격 입력 회귀 테스트

이 작업은 서버 재구축과 병행할 수 있으며, 향후 자체 Virtual HID를 추가할 때 기존 Viewer 프로토콜과 UI를 크게 바꾸지 않게 해준다.
