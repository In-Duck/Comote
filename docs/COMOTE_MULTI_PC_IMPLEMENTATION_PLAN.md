# Comote 다중 PC 원격제어 구현 계획서

작성일: 2026-07-17  
기준 버전: Comote v1.3.0 작업 트리  
목표: 기존 Comote의 1:1 원격제어 기능을 보존하면서, 다수의 Windows PC를 목록·타일·그룹 단위로 모니터링하고 제어하는 운영 도구로 확장한다.

---

## 1. 목표 제품 정의

Comote의 최종 형태는 다음 기능을 제공하는 Windows 다중 PC 원격 관리 프로그램이다.

1. 사용자 계정에 등록된 PC를 목록과 화면 타일로 확인한다.
2. PC를 그룹과 태그로 구성한다.
3. 여러 PC의 화면을 저화질·저프레임으로 동시에 모니터링한다.
4. 특정 PC를 선택하면 기존 Comote의 고화질 1:1 원격제어 화면으로 전환한다.
5. 선택한 PC 또는 그룹 전체에 키보드·마우스 입력, 파일, 실행·종료 명령을 보낸다.
6. 각 작업의 진행률, 성공, 실패, 재시도 결과를 확인한다.
7. 모든 민감 작업에 사용자 권한과 감사 기록을 적용한다.

### 핵심 UX

```text
로그인
  ↓
PC 목록 / 그룹
  ↓
다중 모니터링 타일
  ├─ 더블클릭 → 1:1 고화질 원격제어
  ├─ 다중 선택 → 파일/명령/전원 작업
  └─ 그룹 선택 → 멀티컨트롤
```

## 2. 현재 프로젝트 구성

| 영역 | 현재 역할 | 주요 기술 |
|---|---|---|
| `Host` | 피제어 Windows PC 에이전트 | .NET 10, WinForms, DXGI, FFmpeg, WebRTC |
| `Viewer` | 원격제어 및 호스트 목록 UI | .NET 10, WPF, WebRTC, Supabase |
| `web` | 로그인 및 Pusher 인증·시그널 중계 | Next.js 16, Supabase, Pusher |
| `Distribution` | Host/Viewer 설치기와 업데이트 정보 | Inno Setup, JSON |
| `ApiCheck` | SIPSorcery API 확인용 보조 프로젝트 | .NET |

## 4. 반드시 먼저 해결할 배포 차단 항목

아래 항목이 해결되기 전에는 외부 사용자 대상 배포를 진행하지 않는다.

### 4.1 비밀키 제거 및 교체

- `Host/appsettings.json`, `Viewer/settings.json`에 포함된 Pusher Secret을 제거한다.
- Pusher Secret은 Next.js 서버 환경변수에서만 사용한다.
- 이미 노출된 키는 폐기하고 새 키로 교체한다.
- 예제 설정 파일에는 플레이스홀더만 둔다.

### 4.2 채널 소유권 검증

- `private-control-{hostId}` 인증 시 `hosts.user_id`가 현재 사용자와 같은지 확인한다.
- trigger API도 동일한 소유권 검사를 수행한다.
- 단순 접두사 검사만으로 이벤트 전송을 허용하지 않는다.
- 연결마다 짧은 만료시간의 세션 토큰을 발급한다.

### 4.3 Host 서비스 수정

- 코드와 설치기의 서비스명을 하나로 통일한다.
- 상대 경로 `login.dat` 사용을 중단한다.
- `%ProgramData%\Comote\`에 서비스 설정을 저장한다.
- 사용자 비밀번호 대신 기기 등록 토큰과 갱신 토큰을 사용한다.
- 서비스 계정과 파일 ACL을 명확히 설정한다.

### 4.4 화면 캡처 안정화

- WebRTC 영상과 썸네일 캡처가 동시에 DXGI 객체를 호출하지 않도록 한다.
- 하나의 캡처 루프가 최신 프레임을 생성하고 각 인코더가 복사본을 소비하도록 구성한다.
- `AcquireNextFrame`부터 `ReleaseFrame`까지 예외가 발생해도 항상 정리되도록 한다.

### 4.5 썸네일 비공개화

- 공개 `thumbnails` 버킷을 비공개로 전환한다.
- Viewer가 로그인 후 signed URL을 발급받도록 한다.
- 장기적으로는 Storage JPEG 대신 실시간 모니터링 채널로 교체한다.


초기에는 기존 프로젝트를 유지하면서 `Comote.Shared`와 테스트 프로젝트부터 추가한다. 전체 기능을 한 번에 이동하지 않는다.

### 5.2 스트림 분리

#### 모니터링 스트림

- 목적: 수십~수백 대의 상태 파악
- 권장 해상도: 320×180 또는 타일 크기 기반
- 권장 FPS: 1~5
- 입력: 비활성
- 오디오: 비활성
- 화면 밖 타일: 구독 중단 또는 0.2~1 FPS
- 네트워크 상태에 따라 WebP/JPEG 프레임 또는 저비트레이트 영상 사용

#### 제어 스트림

- 목적: 기존 1:1 원격제어
- 해상도: 원본 또는 사용자 선택
- FPS: 15~60
- 입력, 오디오, 클립보드, 파일 전송 활성
- WebRTC 적응형 비트레이트 사용

#### 원칙

- 모니터링 타일을 열었다고 모든 PC에 고화질 WebRTC 세션을 생성하지 않는다.
- 제어 화면 진입 시에만 고화질 세션을 생성한다.
- Viewer의 CPU, GPU, 네트워크 예산을 기준으로 동시 구독 수를 제한한다.

## 7. Viewer 화면 계획

### 7.1 공통 상단 상태바

- 온라인 PC / 전체 PC
- 활성 모니터링 스트림 수
- 현재 고화질 제어 세션 수
- Viewer CPU·RAM
- 네트워크 송수신량
- 서버 연결 상태
- 사용자와 역할

### 7.2 왼쪽 메뉴

1. 대시보드
2. PC 목록
3. 다중 모니터링
4. 원격 작업
5. 파일 배포
6. 작업 기록
7. 설정

### 7.3 PC 목록

필수 기능:

- 검색
- 온라인/오프라인 필터
- 그룹/태그 필터
- 다중 선택
- 이름, IP, 버전, 시스템 정보 정렬
- 선택 PC 빠른 작업
- 컬럼 표시 설정
- 마지막 접속 시간
- 업데이트 필요 표시

### 7.4 다중 모니터링

필수 기능:

- 그룹 탭
- 열 개수와 타일 비율
- PC 이름·메모 표시
- 온라인·오프라인·오류 상태
- 타일 다중 선택
- 더블클릭으로 1:1 제어
- 화면에 보이는 타일만 실시간 구독
- 마지막 프레임과 마지막 갱신 시간 표시
- 다중 모니터 PC의 모니터 선택

### 7.5 우측 작업 패널

선택 상태에 따라 자동 전환한다.

- 선택 없음: 현재 그룹 설정
- PC 1대: PC 상세 정보와 개별 작업
- PC 여러 대: 일괄 작업
- 제어 세션: 품질·오디오·모니터 설정

### 7.6 원격 작업

탭:

1. 파일 전송
2. 프로그램 실행
3. 프로세스 종료
4. 전원·세션
5. 사용자 정의 작업

목표: 현재 기능을 안전하게 유지할 수 있는 기준선을 만든다.

작업:

- 비밀키 제거 및 회전
- Pusher 채널 소유권 검증
- Host 서비스명과 설치기 통일
- 서비스 기기 토큰 도입
- 캡처 동시성 수정
- 타이머를 `PeriodicTimer` 기반 루프로 변경
- 썸네일 버킷 비공개화
- .NET 패키지 복원 및 Host/Viewer 빌드 성공
- 웹 ESLint 오류 제거
- `Comote.sln`과 기본 테스트 프로젝트 생성

완료 조건:

- 새 계정은 다른 계정의 채널을 인증하거나 trigger할 수 없다.
- Host 서비스가 재부팅 후 자동 로그인·연결된다.
- 2시간 연속 1:1 제어 중 캡처 중단이 없다.
- Host, Viewer, web 빌드와 테스트가 모두 통과한다.

## Phase 1. Fleet Dashboard

목표: 100대 수준의 PC를 목록과 그룹으로 관리한다.

작업:

- Device, Group, DeviceGroup 스키마
- 그룹 생성·이름 변경·삭제
- PC를 그룹에 추가·제거
- 검색, 정렬, 필터, 다중 선택
- MVVM 기반 PC 목록 화면
- Realtime 상태 이벤트 또는 안정화된 폴링
- 마지막 접속 시간과 에이전트 버전 표시

완료 조건:

- 테스트 데이터 1,000대를 목록에서 원활하게 검색·정렬한다.
- PC 100대를 다중 선택해 작업 대상을 만들 수 있다.
- 그룹 변경이 재실행 후 유지된다.

## Phase 2. 다중 모니터링

목표: 선택한 그룹의 PC 화면을 타일로 모니터링한다.

작업:

- Host 모니터링 프레임 생성기
- 모니터링용 전송 채널
- Viewer 가상화 타일 그리드
- 화면 내 타일만 구독
- FPS·품질·해상도 프리셋
- 오프라인·지연·인증 오류 표시
- 타일 더블클릭 시 기존 1:1 제어 연결
- PC별 다중 모니터 선택

완료 조건:

- 1920×1080 Viewer PC에서 50대 타일을 안정적으로 표시한다.
- 타일 화면이 최소 1 FPS로 갱신된다.
- 스크롤 밖 타일의 CPU·네트워크 사용이 감소한다.
- 타일에서 1:1 제어 전환이 3초 내 시작된다.

## Phase 3. 원격 작업과 파일 배포

목표: 선택 PC 또는 그룹에 관리 작업을 실행한다.

작업:

- RemoteJob, RemoteJobTarget, AuditEvent
- Host 작업 수신·실행·보고 모듈
- 다중 파일 전송 UI 보완
- 취소, 재시도, 속도, 진행률
- 원격 저장 경로 선택
- 프로그램 실행 프리셋
- 프로세스 목록 조회·종료
- 재부팅, 종료, 로그오프, 잠금
- 오프라인 PC 작업 만료 또는 재접속 대기 정책

완료 조건:

- 20대 PC에 파일을 배포하고 PC별 결과를 확인한다.
- 실패 PC만 다시 시도할 수 있다.
- 실행·종료·전원 작업이 감사 로그에 남는다.
- Viewer 종료 후 다시 실행해도 진행 중 작업 상태를 복원한다.

## Phase 4. 멀티컨트롤

목표: 기준 PC의 입력을 선택한 여러 PC에 복제한다.

작업:

- 멀티컨트롤 세션 생성·종료
- 키보드만/마우스만/전체 입력 모드
- 해상도와 DPI 기반 좌표 정규화
- 절대 좌표와 상대 좌표 모드
- 입력 전송 지연 측정
- 실패·지연 PC 자동 제외
- 전체 입력 즉시 중단 단축키
- 멀티컨트롤 중 PC별 상태 표시

완료 조건:

- 서로 다른 해상도의 PC 10대에서 동일 UI 요소를 비율 좌표로 클릭한다.
- 한 PC의 연결이 끊겨도 나머지 제어가 유지된다.
- 비상 중단 명령 후 추가 입력이 전송되지 않는다.
- 현재 멀티컨트롤 대상이 화면에 명확히 표시된다.

## Phase 5. 제품 안정화

목표: 외부 배포 가능한 운영 품질을 확보한다.

작업:

- 역할 기반 권한
- 독점/공유 제어 세션
- 감사 로그 조회·내보내기
- 구조화 로그와 크래시 리포트
- 에이전트 자동 업데이트와 롤백
- 설치기 코드 서명
- 네트워크 장애·재연결 테스트
- 장시간·대규모 부하 테스트
- 개인정보와 보안 정책 문서

완료 조건:

- 100대 등록, 50대 모니터링, 1대 고화질 제어를 8시간 유지한다.
- 네트워크 단절 후 자동 복구한다.
- 권한 없는 사용자가 실행·종료·파일 작업을 수행할 수 없다.
- 업데이트 실패 시 이전 버전으로 복구한다.

## 10. 기술 부채 정리 계획

### 코드 구조

- UI 코드와 비즈니스 로직을 분리한다.
- Host/Viewer 공통 프로토콜을 `Comote.Shared`로 이동한다.
- 메시지 타입을 숫자 상수 대신 버전이 있는 DTO로 정의한다.
- 연결, 작업, 장치 상태를 명시적인 상태 머신으로 관리한다.

### 비동기 처리

- Timer 기반 비동기 호출을 `PeriodicTimer`와 취소 토큰으로 교체한다.
- 모든 장시간 작업에 취소·타임아웃을 적용한다.
- 다중 파일 전송 동시성 제한을 둔다.
- UI 이벤트의 `async void`는 최상위 이벤트 핸들러로만 제한한다.

### 오류 처리

- 오류 코드 체계를 만든다.
- 사용자 메시지와 진단 로그를 분리한다.
- 빈 `catch`를 제거한다.
- Host 작업 결과에 오류 코드와 재시도 가능 여부를 포함한다.

### 테스트

- 권한 및 채널 소유권 테스트
- 좌표 변환 테스트
- 업데이트 해시·서명 테스트
- 파일명 및 저장 경로 테스트
- 작업 상태 전이 테스트
- 그룹 CRUD 테스트
- 온라인/오프라인 판정 테스트

## 13. 최종 판단

현재 Comote는 새로 폐기하고 시작할 단계가 아니다. 이미 다음의 어려운 기반이 구현되어 있다.

- Windows 화면 캡처
- WebRTC 영상·오디오
- 키보드·마우스 입력
- 파일 전송
- 클립보드
- 멀티모니터
- 호스트 등록과 상태 수집

따라서 최적의 접근은 다음과 같다.

1. 보안과 서비스 구조를 먼저 정상화한다.
2. 기존 1:1 제어 엔진은 보존한다.
3. Viewer의 로비를 Fleet Dashboard로 새로 만든다.
4. 모니터링 스트림과 제어 스트림을 분리한다.
5. 그룹, 원격 작업, 멀티컨트롤을 순서대로 추가한다.

이 방식은 기존 기술 투자를 살리면서도 LinkIO와 유사한 다중 PC 운영 경험을 독립적인 구조로 구현할 수 있다.
