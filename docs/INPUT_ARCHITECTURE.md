# Comote 원격 입력 구조

## 목표

물리 마우스와 키보드가 연결되지 않은 Windows PC도 원격 조작한다. 기본 경로는
Windows `SendInput`이고, 테스트 서명된 Comote 전용 가상 HID 드라이버를 선택형
입력 백엔드로 함께 제공한다.

## 입력 경로

앞의 세 단계는 두 백엔드가 공통이다.

1. 매니저가 원격 영상의 실제 표시 영역을 기준으로 좌표를 0~1 범위로 정규화한다.
2. 마우스 이동·버튼·휠과 키보드 이벤트를 WebRTC DataChannel로 전송한다.
3. 클라이언트가 `HostInputProtocol`로 프레임을 엄격 검증하고 선택된 모니터의
   가상 데스크톱 좌표로 복원한다.

이후는 선택된 백엔드에 따라 갈린다.

- **SendInput** — `SendInputBackend`가 Windows 입력 큐에 직접 주입한다.
- **가상 HID** — `VirtualHidInputBackend`가 `InputBrokerClient`로 명명 파이프에
  요청을 보내고, LocalSystem으로 도는 `ComoteInputBroker` 서비스가 Phase 2 커널
  드라이버와 VHF를 거쳐 실제 HID 리포트를 만든다.

마지막으로 클라이언트가 이벤트 종류를 매니저에 응답하고, 매니저 원격창에
`입력: 연결 중`, `준비`, `수신 확인`을 표시한다.

## 입력 모드

| 모드 | 구현 | 용도 | 제한 |
|---|---|---|---|
| 모드 1 | Windows SendInput | 일반 데스크톱과 대부분의 앱 | 잠금 화면, UAC 보안 데스크톱, 일부 보호 프로그램 |
| 모드 2 | Comote 가상 키보드·마우스 HID | SendInput을 거부하는 앱 | 테스트 서명 부팅, 드라이버 설치·재부팅, Broker 서비스 필요 |
| 모드 3 | 저수준 전용 HID/필터 | 호환성 최우선 환경 | 배포·보안·유지보수 비용이 가장 큼 |

모드 2 드라이버는 VirtualHidPreview 번들에 포함되며, 일회용 VM에서만 검증하는
테스트 서명 자산이다. 모드 3은 아직 인터페이스만 있다. 타사 드라이버 파일은
복사하지 않고 Comote 전용으로 개발·서명한다.

## 백엔드 선택

기본값은 모드 1이다. 클라이언트 실행 시 아래 중 하나로 바꾼다.

- `--virtual-hid` 또는 `--send-input`
- `--input-backend virtualhid` / `--input-backend=sendinput`
- 환경 변수 `COMOTE_INPUT_BACKEND`

서로 충돌하는 옵션을 함께 주면 시작을 거부한다. 모드 1이 실패했을 때 모드 2로
자동 전환하지는 않는다.

## 현재 보장 범위

- 물리 마우스와 키보드 연결은 필요하지 않다.
- 클라이언트는 관리자 권한을 요구하지 않는다(`asInvoker`). 권한이 필요한 입력
  주입은 LocalSystem Broker 서비스가 맡고, 클라이언트는 `Comote Input
  Controllers` 로컬 그룹 토큰으로 그 파이프를 사용한다.
- 클라이언트는 파이프 소유자가 LocalSystem인지 확인한 뒤에만 입력을 보낸다.
- 원격 Windows 사용자가 로그인된 대화형 세션이어야 한다.
- Windows 잠금 화면과 UAC 보안 데스크톱은 두 모드 모두 제어할 수 없고,
  Ctrl+Alt+Del도 가상 HID 경로로는 보낼 수 없다.
- 텍스트와 IME 입력은 키보드 이벤트로 번역한다. 임의 유니코드 주입 수단은 없다.
- 연결 종료, 창 비활성화, PC 전환 시 눌린 키와 버튼을 모두 해제한다.
- 다중 모니터는 가상 데스크톱 좌표와 선택 모니터 원점을 함께 적용한다.

## 남은 완료 조건

테스트 서명 모드 장치 열거, 무입력장치 PC 입력 시험, 설치·삭제·복구 자동화는
Phase 1·2 게이트와 VirtualHidPreview 워크플로로 완료했다. 남은 항목은 다음과
같다.

1. EV 코드 서명과 Microsoft 드라이버 서명 절차 완료
2. 모드 1 실패 시 모드 2로 전환하는 관리자 UI 제공
3. 입력 감사 로그에 전송, 클라이언트 수신, OS 주입 결과를 분리해 기록
4. 프로덕션 배포·업데이트·롤백 경로
